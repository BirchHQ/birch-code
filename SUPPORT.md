# Getting help with Birch

## Where to go

| I want to… | Go to |
|---|---|
| Ask a question or get help | [Q&A discussions](https://github.com/BirchInnovation/birch-code/discussions/categories/q-a) |
| Propose or discuss an idea | [Ideas discussions](https://github.com/BirchInnovation/birch-code/discussions/categories/ideas) |
| Report a bug | [Bug report form](https://github.com/BirchInnovation/birch-code/issues/new/choose) |
| Report a security problem | [SECURITY.md](SECURITY.md) — privately, never as a public issue |
| See what's planned | [Roadmap](https://github.com/orgs/BirchInnovation/projects/1) |

If you are not sure whether something is a bug, start a Q&A discussion — confirmed bugs get promoted to issues.

## Finding your Birch version

Open the gear menu and choose **Check for updates…** — the dialog shows *Current version*.

## Finding your logs

Birch writes a daily log file (kept for 14 days):

- **macOS:** `~/Library/Application Support/birch/logs/birch-YYYYMMDD.log`
- **Windows:** `%APPDATA%\birch\logs\birch-YYYYMMDD.log`

If Birch fails to launch, it shows a **“Birch could not start”** window with two useful buttons: **Copy details** (copies the diagnostic text — paste it into your bug report) and **Open logs folder**.

> **Before you attach anything:** log files can mention repository names, remote URLs and file paths. Skim them and remove anything you consider private — the bug report form asks you to confirm you have done this.
